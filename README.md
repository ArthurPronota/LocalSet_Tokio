# LocalSet из Tokio — механизм, который позволяет запускать !Send future (не потокобезопасные) в одном потоке

## Что делает этот код

Код демонстрирует **`LocalSet`** из Tokio — механизм, который позволяет запускать **`!Send` future** (не потокобезопасные) в **одном потоке**. В примере создаётся `LocalSet`, внутри него запускаются 5 задач через `spawn_local`, каждая увеличивает общий счётчик `Rc<RefCell<i32>>`, после чего выводится итоговое значение.

## Разбор по шагам

### 1. Однопоточный рантайм

```rust
#[tokio::main(flavor = "current_thread")]
async fn main() {
```

- **`flavor = "current_thread"`** — рантайм Tokio работает **в одном потоке**.
- Это **необходимое условие** для `LocalSet`: задачи не должны мигрировать между потоками.
- В многопоточном рантайме (`multi_thread`) `LocalSet` тоже работает, но задачи всё равно привязаны к потоку, где создан `LocalSet`.

### 2. Создание `LocalSet`

```rust
let loc = task::LocalSet::new();
```

- `LocalSet::new()` создаёт **пустой набор задач**, которые будут выполняться **в одном потоке**.
- `LocalSet` **не является** рантаймом сам по себе — это **контейнер**, который нужно **запустить** через `run_until` или `block_on`.
- Внутри `LocalSet` задачи запускаются через **`spawn_local`**, а не через `tokio::spawn`.

### 3. Запуск `LocalSet`

```rust
loc.run_until(
async move {
    // ...
})
.await;
```

- **`run_until(future)`** — запускает `LocalSet` и выполняет переданный `future` **до завершения**.
- Пока `future` не завершится, `LocalSet` **опрашивает** все задачи, добавленные через `spawn_local`.
- `run_until` **заимствует** `LocalSet` (`&self`), возвращает `RunUntil` (future), который нужно `.await`-ить.

### 4. Создание `!Send` счётчика

```rust
let counter = Rc::new(RefCell::new(0));
```

- **`Rc<i32>`** — счётчик ссылок **без атомиков**. **Не является `Send`** — его нельзя передать в другой поток.
- **`RefCell<i32>`** — внутренняя изменяемость с проверками во время выполнения. **Не является `Sync`**.
- Вместе `Rc<RefCell<i32>>` — **`!Send`**, его **нельзя** использовать в `tokio::spawn`.

### 5. Вектор для хендлов

```rust
let mut handls = vec![];
```

- Вектор `JoinHandle` — чтобы дождаться завершения всех задач.
- Каждый `spawn_local` возвращает `JoinHandle<()>`.

### 6. Запуск 5 задач

```rust
for i in 0..5 {
    let counter = counter.clone();
    handls.push(
        task::spawn_local(
            async move {
                *counter.borrow_mut() += 1;
                println!("Task: {} is done", i);
            }
        )
    );
}
```

Разберём:

- **`counter.clone()`** — клонирует `Rc`, увеличивая счётчик ссылок. Теперь у каждой задачи **своя** копия `Rc`, указывающая на **тот же** `RefCell`.
- **`task::spawn_local(...)`** — порождает **`!Send` future** на текущем `LocalSet`.
  - Работает **только внутри** `LocalSet` (внутри `run_until`).
  - В отличие от `tokio::spawn`, **не требует `Send`**.
  - Возвращает `JoinHandle`, который можно `.await`-ить.
- **`async move { ... }`** — захватывает `counter` и `i` **по значению**.
- **`*counter.borrow_mut() += 1`** — изменяемое заимствование `RefCell`, увеличение счётчика на 1.
  - `borrow_mut()` — берёт `RefMut` (изменяемую ссылку).
  - `*...` — разыменование.
  - `+= 1` — инкремент.
  - `RefMut` **дропается** в конце выражения, освобождая заимствование.
- **`println!("Task: {} is done", i)`** — печатает номер задачи.

### 7. Ожидание завершения задач

```rust
for h in handls {
    h.await.unwrap();
}
```

- Перебираем все `JoinHandle`.
- **`.await`** — ждём завершения каждой задачи.
- **`.unwrap()`** — разворачиваем `Result` (паника, если задача упала).

### 8. Вывод итогового значения

```rust
println!("Итоговое значение счётчика: {}", *counter.borrow());
```

- **`counter.borrow()`** — неизменяемое заимствование `RefCell`.
- **`*...`** — разыменование, получаем `i32`.
- Вывод: **5**, потому что 5 задач увеличили счётчик на 1 каждая.

## Что происходит «под капотом»

### `LocalSet` и `spawn_local`

- `LocalSet` хранит **очередь задач**, привязанных к текущему потоку.
- `spawn_local` добавляет задачу в эту очередь.
- `run_until` крутит **цикл событий**: опрашивает задачи из очереди и переданный `future`.
- Задачи **не мигрируют** между потоками — поэтому `!Send` типы **безопасны**.

### Почему `Rc` и `RefCell` работают

- `Rc` не потокобезопасен, но **не покидает поток** — все клоны в одном `LocalSet`.
- `RefCell` не `Sync`, но **доступ только из одного потока** — гонок нет.
- Компилятор **не даст** использовать `Rc` в `tokio::spawn`, но **даст** в `spawn_local`.

### Порядок вывода

Задачи выполняются **конкурентно** (не параллельно — поток один), порядок **не гарантирован**:

```
Task: 2 is done
Task: 0 is done
Task: 4 is done
Task: 1 is done
Task: 3 is done
Итоговое значение счётчика: 5
```

Или в любом другом порядке — но итог всегда **5**.

## Что было бы без `LocalSet`

```rust
tokio::spawn(async move {
    *counter.borrow_mut() += 1;   // ❌ ошибка компиляции
});
```

Компилятор скажет:

```
error[E0277]: `Rc<RefCell<i32>>` cannot be sent between threads safely
```

`tokio::spawn` требует `Send`, а `Rc<RefCell<i32>>` — **не `Send`**.

## Когда использовать `LocalSet`

| Ситуация | `LocalSet` нужен? |
|---|---|
| Работа с `Rc`, `RefCell` | ✅ Да |
| Работа с `*mut T`, сырыми указателями | ✅ Да |
| GUI-библиотеки (UI-типы часто `!Send`) | ✅ Да |
| Интеграция с `!Send` библиотеками | ✅ Да |
| Обычные `Send` задачи | ❌ Нет, `tokio::spawn` проще |
| Многопоточные вычисления | ❌ Нет, нужен `multi_thread` |

## Сравнение `spawn` и `spawn_local`

| | `tokio::spawn` | `task::spawn_local` |
|---|---|---|
| Требует `Send` | ✅ Да | ❌ Нет |
| Где работает | В любом рантайме | Только внутри `LocalSet` |
| Миграция между потоками | ✅ Да | ❌ Нет |
| Работа с `Rc`, `RefCell` | ❌ | ✅ |
| Требует `'static` | ✅ Да | ✅ Да |
| Возвращает | `JoinHandle<T>` | `JoinHandle<T>` |

## Сводная таблица

| Элемент | Роль |
|---|---|
| `#[tokio::main(flavor = "current_thread")]` | Однопоточный рантайм |
| `LocalSet::new()` | Создаёт набор локальных задач |
| `run_until(future)` | Запускает `LocalSet` и ждёт `future` |
| `Rc<RefCell<i32>>` | `!Send` счётчик, безопасный в одном потоке |
| `spawn_local` | Порождает `!Send` задачу в `LocalSet` |
| `.await.unwrap()` | Ждёт завершения задачи |
| `counter.borrow()` | Читает итоговое значение |

## Итог

- **`LocalSet`** — механизм Tokio для запуска **`!Send` future** в **одном потоке**.
- **`spawn_local`** — единственный способ запустить `!Send` задачу, работает **только внутри `LocalSet`**.
- **`run_until`** — запускает `LocalSet` и выполняет переданный `future` до завершения, опрашивая все локальные задачи.
- **`Rc<RefCell<i32>>`** — типичный пример `!Send` типа: не потокобезопасен, но безопасен в одном потоке.
- **Используйте `LocalSet`**, когда работаете с `Rc`, `RefCell`, `*mut`, GUI-типами или `!Send` библиотеками.
- **Не используйте `LocalSet`** для обычных `Send` задач — `tokio::spawn` проще и эффективнее.
- В вашем примере: 5 задач увеличивают общий счётчик на 1, итог — **5**.
